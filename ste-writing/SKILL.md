# STE 清楚寫作與文字潤飾

將文字寫得清楚、具體、自然，讓讀者理解作者的意思。支援從需求生成新稿，以及改寫、潤飾、摘要和翻譯既有文字；適用範圍由文字的用途決定，與是否存成 Markdown 無關。

## 使用流程

1. 每次使用先讀取 [ASD-STE100 具體規則摘要](references/asd-ste100-rules.md)。其中有版本、規則編號和英文規則內容；區分官方規則與下方的通用寫作調整。
2. 從請求判斷語言、讀者、用途、語氣和修改幅度。資料足夠就直接處理。未指定語言時沿用對話語言；中文預設繁體。使用者指定的文體、格式和範例優先。
3. 生成新稿時，以已知事實和使用者的寫作目的組織內容。改寫時，先辨識必須保留的意思、資料、語氣與不確定性，再調整措辭和結構。翻譯以目標語言的自然用法表達相同意思。
4. 依下列規則完成文字。需要跨文體的改寫示範時，讀取 [不同情境的範例](references/genre-examples.md)。
5. 交付前比對事實與意圖，再檢查讀起來是否自然。預設直接提供可使用的成品；使用者要求對照、批註或理由時才附上修改說明。

## 規則如何套用

### 一般寫作：依語言和文體調整

將規則摘要轉成以下寫作行為。這些是本 skill 的跨語言與文體調整，不是官方新增的中文規則。

- **先讓讀者知道重點。** 說明結果、問題或寫作目的，再提供必要背景。保留故事、演講或其他文體刻意安排的鋪陳。
- **用動詞交代動作。** 將「進行設定調整」寫成「修改設定」。遇到「賦能、對齊、閉環、收斂、落地」等抽象說法，依上下文交代實際動作、對象或結果；資訊不足就保留缺口。在數學等領域具有精確意義的詞照常保留。
- **寫清楚誰對什麼做了什麼。** 指涉要明確，但原文沒有負責人時，不自行指派。執行者未知或不重要時，可依語言習慣使用自然的被動句。
- **拆開資訊過多的句子。** 每句有一個主要意思，保留條件、例外、因果與轉折。保留必要的主詞、受詞與連接詞，讓短句仍然完整。
- **讓段落有邏輯。** 一段圍繞一個主題，依讀者理解的順序展開。需要時使用「因為、因此、但是、如果」說明關係；依內容變化句長，避免每句節奏相同。
- **讓術語一致，讓日常用語自然。** 同一專業概念使用相同名稱。讀者不熟悉的術語首次出現時簡短解釋。一般敘述仍可自然換詞，避免為一致性重複每個普通名詞。
- **用內容取代空泛評語。** 有依據時，將「大幅提升、全面優化、順利完成」換成具體改動、結果或判定標準。未知數字與成果不能補造。
- **讓語氣符合情境。** 保留信件的禮貌、對話的溫度、文章的觀點與學術論證的精確程度。詩歌、幽默和創作中的刻意修辭，依使用者目的保留；以讀者能理解為調整依據。

### 英文技術寫作：依摘要採用 STE 規則

依規則摘要中的詞彙、動詞、句長、段落及標點限制處理。需要判定某個英文詞的核准詞性、詞義或形式時，查閱適用版本的官方詞典；一般常用詞不等於已獲 STE 核准。

本 skill 附的是重點規則摘要，沒有完整受控詞典。使用者要求正式符合 ASD-STE100 時，取得並核對指定版本的完整規則與詞典；只有完成相應查核後，才能陳述符合的範圍。一般文字潤飾直接使用摘要與本地語言規則，不宣稱標準合規。

### 中文及其他語言：採用清楚表達的方法

依該語言的語法、標點和自然表達改寫。英文詞數限制不換算成中文字數，也不將英文的冠詞、時態或詞性規則硬套到其他語言。保留必要資訊，以讀者能否一次理解來決定拆句與分段。

## 各種文字的處理方式

| 情境 | 寫作重點 |
|---|---|
| 日常回覆、聊天、問答 | 直接回答，再補上理解答案所需的理由；短問題通常用短段落。 |
| 信件、訊息、客服回覆 | 清楚交代目的、目前狀況和需要對方做的事；保留適度禮貌。 |
| 文章、社群貼文、演講稿 | 保留觀點、聲音和段落節奏，刪除沒有內容的套話。 |
| 報告、摘要、學術文字 | 區分觀察、解釋與推論，保留論證、專業術語、限制與引用。 |
| 介面文案、通知、錯誤訊息 | 說明發生什麼，以及使用者可採取的下一步；只承諾產品確實支援的行為。 |
| 交接、工作紀錄 | 清楚區分已修改、已測試、已部署與待辦；只列出有用且有資料的項目。 |
| 操作步驟、教學 | 先交代前提，再依順序給出動作；必要的條件與警告放在相關動作之前。 |

這些情境是例子，其他面向真人的文字也適用。沿用使用者要求的載體與格式，包括純文字、Markdown、HTML、文件正文、簡報文案及結構化資料中的人類可讀字串。只修改授權的文字範圍，保留周圍語法與識別字。

## 保留原意與可用性

- 保留事實、立場、時間、數字、單位、否定條件、限制和承諾強度。「預計完成」不能改成「已完成」；「可能改善」不能改成「已改善」。
- 保留引用、來源、公式、變數、名稱、法律或安全用語。程式碼、命令、路徑、網址、設定鍵和錯誤識別碼維持原樣，除非使用者明確要求修改。
- 不自行新增負責人、期限、因果、測試結果或效能數據。新增的建議與推論要能和既有事實區分；會影響使用的資訊缺口簡短標明。
- 一般潤飾預設調整措辭與句子；依需要改善段落銜接。使用者要求重寫、縮短或重組時，再相應調整結構，保留關鍵內容。
- 保留指定的標題、表格、連結、引用區塊、標記與佔位符。讓格式服務閱讀：連續敘述用段落，平行資訊用清單，比較用表格，步驟用編號。

交付前確認：意思與原文或需求一致；沒有把未知事項寫成事實；語氣符合文體；術語與數字正確；刪除的內容不影響理解或操作；成品可直接放進使用者指定的情境。
